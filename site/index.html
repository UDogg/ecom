How a request travels

The browser only ever talks to the BFF. It holds the session, checks the role, validates every field against a route table compiled into it, and signs the call; each core service refuses anything it did not sign. Events leave through a transactional outbox, so nothing is lost when the broker is down.

What makes it different

The API is code

Every route the BFF serves is one line of Go: its fields, its role, its upstream path, its response schema. No catch-all proxy; anything else is a 404 before it reaches a service.

Correct under failure

Stock is reserved at checkout, payments are idempotent and reconciled, a capture for an expired order is refunded automatically, and events survive a broker outage.

Break-glass, audited

When the BFF is down, operators get a 15-minute token acting as one named user, with a reason, recorded in an append-only table. Machine accounts get narrow SYSTEM tokens.

Sized by the machine

Postgres, the JVM, Go, gunicorn and uvicorn all size themselves from their container; the run script gives each a share of the instance. A bigger instance is used fully with no edits.

Fast where it matters

Public catalog reads are micro-cached and coalesced in the BFF; the storefront is precompressed in memory; queries have matching indexes; Java starts in 2.9 s from a class-data archive.

Kept current

Dependabot updates every ecosystem weekly, and CI fails on any deprecated API in Python, Go and Java, so updates stay small and boring.

Run it locally

Docker and Python 3 are all it needs. One command checks the machine, generates secrets, builds, starts, waits for health and seeds the shop.

git clone https://github.com/UDogg/ecom && cd ecom
./run.sh
# → http://localhost:8080

Deploy it

One CloudFormation stack: a Graviton instance, HTTPS by Caddy, no SSH, nightly backups to S3.

AWS_REGION=eu-west-1 deploy/aws/deploy.sh
# → https://<ip>.sslip.io
deploy/aws/deploy.sh InstanceType=t4g.medium   # resize
